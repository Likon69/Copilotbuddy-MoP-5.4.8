# CopilotBuddy MoP

World of Warcraft 5.4.8 (Mists of Pandaria, build 18414) bot written in C# (.NET 10, WPF, x86). The API surface and the architecture come from Honorbuddy 5.4.8, decompiled for reference and re-implemented. The bot refuses to attach to anything other than build 18414 (`Styx/StyxWoW.cs`, `MainWindow.xaml.cs`).

This is the MoP sibling of [CopilotBuddy](https://github.com/Likon69/CopilotBuddy) (WotLK 3.3.5a).

## What differs from the Honorbuddy 5.4.8 port

Everything below is on top of, or in place of, what the original 5.4.8 bot does.

**Runtime.** Rebuilt on .NET 10 with a WPF UI, still x86 to match the client. The main window, settings, plugins, process selector and error dialogs are XAML, not the original forms.

**Navigation.** Honorbuddy reached Recast/Detour through `Tripper.RecastManaged.dll`, a mixed-mode C++/CLI assembly. .NET 10 cannot load mixed-mode assemblies at all, so that path is gone: Detour is reached through `Navigation.dll`, a pure native C++ wrapper (see [Navigation-C-](https://github.com/Likon69/Navigation-C-)). `MeshNavigator` and `DefaultHeightProvider` are installed the way the 5.4.8 executable installs them. The mmaps are 4x4 sub-tile `.mmtile` files (16 Detour sub-tiles per ADT) generated by the [C# extractor](https://github.com/Likon69/extractor-csharp); no other mmap format is supported.

**SafeLaunch.** `Styx/SafeLaunch/SafeLauncher.cs`, called from `CustomStartup` before the WPF application starts. If the process is not already running as SYSTEM, it extracts an embedded PsExec under `Cache/` with a randomized name, relaunches itself as SYSTEM with the original command line plus a `/startpipe=<guid>` argument, and relays the child output back through a named pipe. `MiniLoader.exe` is embedded next to it.

**Anti-detection.** Backported from the Honorbuddy Legion build: the GreenMagic `Executor` pads its injected ASM with randomized opcodes, randomizes its allocation size and names its events in GUID format. The D3D9 `EndScene` hook matches the Windows 10 prologue and logs the bytes when a prologue is unknown, which the original hook did not do.

**Gameplay backports from Legion.** `CommonCoroutines.SleepForRandomReactionTime` and `SleepForRandomUiInteractionTime`, an awaitable `SummonGroundMount`, a four second mounted grace period in `Targeting` plus an `IsEvadeRunningBack` removal filter, a mailbox fallback through `Query` in LevelBot, and vendoring that sells items one by one with a delay instead of in a burst.

**New profile tag.** `SetNavType`, to override the navigation type from a quest order; it does not exist in Honorbuddy.

**Port corrections.** A number of places where the first pass did not match the 5.4.8 executable have been fixed against the decompile rather than left as written: the `Spell_C__CastSpell` / `CastSpell2` offsets (no spell was ever cast), `Mount.ActionLandAndDismount`, the Roslyn metadata reference cache (recreating references per profile condition exhausted the 32-bit address space), settings directories resolved from the bot assembly, SQLite disposal in ArchaeologyBuddy. See the git log for the full list.

## Botbases

In tree, under `Bots/` unless noted: ArchaeologyBuddy, BGBuddy, DungeonBuddy, Gatherbuddy, Grind (LevelBot), Professionbuddy, Quest, plus `GrindBuddy2` and `NewMixedMode`. BGBuddy covers the MoP battleground set: Warsong Gulch, Arathi Basin, Eye of the Storm, Alterac Valley, Strand of the Ancients, Isle of Conquest, Twin Peaks, Battle for Gilneas, Temple of Kotmogu, Silvershard Mines, Deepwind Gorge. Further botbases, plugins and combat routines are loaded at runtime from `bin/.../Bots/`, `Plugins/` and `Routines/`.

## Build

```
dotnet build CopilotBuddy.csproj -c Release
```

The output lands in `bin/Release/net10.0-windows7.0/` with `Navigation.dll`, `FASM.DLL`, `Data.bin`, `Tripper.Tools.dll` and the runtime content folders. The native navigation wrapper is built separately with Visual Studio 2022.

## Limitations

Build 18414 only. Nothing else is supported, and no other client or expansion is a target.
